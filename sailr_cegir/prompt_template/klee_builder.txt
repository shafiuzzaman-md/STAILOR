MISSION OBJECTIVE: ONE-SHOT VULNERABILITY VERIFICATION
======================================================
Your GOAL is to construct a harness that:
1. Reaches the target line (`REACH_ASSERT`).

ASSERTION PROTOCOL (CRITICAL ORDERING)
======================================
1. **ENVIRONMENT MACROS:**
   - `REACH_ASSERT` and `BUG_ASSERT(cond)` are injected automatically by the environment.
   - **DO NOT** `#define` them yourself. Just call them.
   - **DO NOT** use `#ifndef` checks for them. Redefining them breaks log parsing.

2. **PLACEMENT & ORDER (NON-NEGOTIABLE):**
   - **Location:** Assertions must be placed **IMMEDIATELY BEFORE** the Target Statement.
   - **NO EXPRESSIONS:** `BUG_ASSERT` and `REACH_ASSERT` are **VOID STATEMENTS**.
     - *Wrong:* `if (BUG_ASSERT(x) && cond) { ... }` (Syntax Error!)
     - *Wrong:* `int x = REACH_ASSERT;`
     - *Right:* ```c
       BUG_ASSERT(x < limit);
       if (cond) { ... }
       ```
   
   - **Order:** `BUG_ASSERT` **MUST** come before `REACH_ASSERT`.
     - *Reason:* `REACH_ASSERT` is a terminal event (klee_assert(0)). If placed first, the bug check is never run.
     
     **CORRECT PATTERN:**
     ```c
     /* 1. Assert Safety (Pre-Condition) */
     BUG_ASSERT(x < limit); 
     
     /* 2. Assert Reachability (Stop here if safe) */
     REACH_ASSERT; 
     
     /* 3. Execute Target Statement */
     dangerous_op(x, y);
     ```

ASSUMPTION INVARIANTS (ANTI-FALSE POSITIVE)
===========================================
- **Consistency:** Environment assumptions (`klee_assume`) must be identical for both reachability and bug verification.
- **No Forcing:** Do NOT add new assumptions or restrict variables solely to trigger an assertion failure. 
- **Sanity vs. Bug:** If a bug does not trigger under the environment assumptions required to reach the target, the code is safe. Do NOT relax environment constraints to "force" a bug.

ASSUMPTION STRATEGY
==============================
1.  **Steering Variables (Environment):**
    - Variables required ONLY to guide control flow to the target (e.g., `mode`, `type`).
    - *Action:* Use `klee_assume(flag == TRUE)` to prune irrelevant paths.
2.  **Vulnerability Variables (Bug Logic):**
    - Variables involved in the vulnerability (lengths, indices, counts, offsets).
    - **Rule:** These MUST be FULLY SYMBOLIC and unconstrained.
    - **Reasoning:** Extreme values (0, MAX_INT) are the intended bug triggers.
    - *Action:* `klee_make_symbolic(&val, sizeof(val), "val")` without any `klee_assume`.
3.  **Container Capacity (CONCRETE ONLY):**
    - When mocking structs (dictionaries, vectors, lists), set `size`/`capacity` fields to **CONCRETE** constants.
    - **Reason:** Making capacity symbolic without matching `malloc` size causes False Positives.
    - *Action:* Set `d->size = 16;` and allocate `d->buf = malloc(16 * sizeof(entry));`.

POINTER / ALLOCATOR MODELING
============================
- **Pointer Values (CRITICAL):**
  - NEVER make a pointer variable symbolic: `klee_make_symbolic(&ptr, sizeof(ptr), "ptr")`.
  - **Reason:** This creates a random garbage address (e.g., 0x1234) which causes an immediate SEGFAULT.
  - **Correct Pattern:** Allocate memory, *then* make the content symbolic:
    ```c
    /* WRONG */ klee_make_symbolic(&ptr, sizeof(ptr), "ptr"); // Crash!
    /* RIGHT */ ptr = malloc(sizeof(Obj)); klee_make_symbolic(ptr, sizeof(Obj), "obj");
    ```

- **Single Source of Truth (CRITICAL):**
  - When checking for buffer overflows, you MUST define the capacity as a MACRO.
  - **Rule:** Use this macro for BOTH the allocation and the assertion.
  - **Prohibited:** Do NOT use magic numbers (e.g., `4096`) in `BUG_ASSERT`.
  
  **CORRECT PATTERN:**
  ```c
  #define ENTRY_CAPACITY 4096  /* 1. Define once */
  
  /* 2. Allocate using macro */
  char *buf = malloc(ENTRY_CAPACITY);
  
  /* 3. Assert using macro (Logical link is clear) */
  BUG_ASSERT(len < ENTRY_CAPACITY);
