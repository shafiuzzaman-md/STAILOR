ASSERTION PROTOCOL
==================
1. **MACRO DEFINITIONS (REQUIRED):**
   - You MUST inject the following definitions at the top of the harness:
     ```c
     #ifndef REACH_ASSERT
     #define REACH_ASSERT klee_assert(0 && "REACH_ASSERT")
     #endif
     #ifndef BUG_ASSERT
     /* Use #cond to preserve the meaningful macro name in the log */
     #define BUG_ASSERT(cond) klee_assert((cond) && "BUG_ASSERT: " #cond)
     #endif
     ```

2. **PLACEMENT & ORDER (NON-NEGOTIABLE):**
   - **Rule:** You MUST write the actual code. **NO PLACEHOLDERS.**
     - *Wrong:* `/* BUG_ASSERT(len < CAP); REACH_ASSERT; */` (Validator will reject this comment!)
     - *Right:* `BUG_ASSERT(len < ENTRY_CAP); REACH_ASSERT;` (Actual executable code)

   - **Control Flow Rule (CRITICAL):**
     - If the Target Line is a control flow statement (`if`, `while`, `for`, `switch`), you MUST place the assertions **BEFORE** the statement, not inside the block.
     - *Reason:* The condition itself (e.g., `arr[i]`) often contains the crash. If you place assertions inside, they will be unreachable if the crash happens first.
     - *Wrong:* `if (cond) { BUG_ASSERT(...); ... }`
     - *Right:* ```c
       BUG_ASSERT(x < limit); /* Check BEFORE the if */
       REACH_ASSERT;
       if (arr[x] == 0) { ... }
       ```

   - **Order:** `BUG_ASSERT` **MUST** come before `REACH_ASSERT`.
   - *Reason:* `REACH_ASSERT` is a terminal event (`klee_assert(0)`). If placed first, the bug check is never run.

ASSUMPTION INVARIANTS (ANTI-FALSE POSITIVE)
===========================================
- **Consistency:** Environment assumptions (`klee_assume`) must be identical for both reachability and bug verification.
- **No Forcing:** Do NOT add new assumptions or restrict variables solely to trigger an assertion failure. 
- **Sanity vs. Bug:** If a bug does not trigger under the environment assumptions required to reach the target, the code is safe. Do NOT relax environment constraints to "force" a bug.

ASSUMPTION STRATEGY
===================
1. **Steering Variables (Environment):**
   - Variables required ONLY to guide control flow (e.g., `mode`, `type`).
   - *Action:* Use `klee_assume(flag == TRUE)` to prune irrelevant paths.

2. **Vulnerability Variables (Bug Logic):**
   - Variables involved in the vulnerability (lengths, indices, counts).
   - **Rule:** These MUST be FULLY SYMBOLIC and unconstrained.
   - **Scope Rule (CRITICAL):** If a variable is used in a `BUG_ASSERT` inside a target function (outside `main`), it **MUST be defined as a Global Variable**.
     - *Wrong:* `int main() { int limit; ... } void target() { BUG_ASSERT(x < limit); }` (Undefined!)
     - *Right:* `int limit; /* Global */ void target() { BUG_ASSERT(x < limit); } int main() { ... }`

POINTER / ALLOCATOR MODELING
============================
1. **The Decoupling Principle (CRITICAL):**
   - **Problem:** KLEE concretizes any symbolic size passed to `malloc`.
   - **Rule:** Decouple the **Capacity** (Physical Size) from the **Length** (Logical Size).
   - **Pattern:**
     1. Allocate a **Concrete Max Capacity** (e.g., `#define CAP 64`).
     2. Make the **Logical Length** symbolic.
     3. **Constraint Logic:**
        - To reach the code, assume `len >= 0`.
        - **TO FIND THE BUG:** Do **NOT** assume `len <= CAP`. Let `len` be large!
   
   *Right (Fully Symbolic Logic):*
   ```c
   #define MAX_CAP 64
   int len; klee_make_symbolic(&len...);
   /* klee_assume(len <= MAX_CAP);  <-- DO NOT DO THIS! BLOCKS THE BUG! */
   
   char *buf = malloc(MAX_CAP); // Concrete allocation (Safe & Fast)
   klee_make_symbolic(buf, MAX_CAP, "buf");
   
   target_func(buf, len); // 'len' can be > 64, triggering the overflow!

2. **Pointer Values (CRITICAL):**
   - **NEVER** make a pointer variable symbolic: `klee_make_symbolic(&ptr, sizeof(ptr), "ptr")`.
   - **Reason:** This creates a random garbage address (e.g., 0x1234) which causes an immediate SEGFAULT when dereferenced.
   - **Correct Pattern:** Allocate memory first, *then* make the content symbolic:
     ```c
     /* WRONG - CRASHES IMMEDIATELY */
     char *ptr;
     klee_make_symbolic(&ptr, sizeof(ptr), "ptr"); 
     
     /* RIGHT - SAFE */
     char *ptr = malloc(64);
     if (ptr) klee_make_symbolic(ptr, 64, "ptr_content");
     ```

3. **Single Source of Truth (CRITICAL):**
   - **Rule:** Define the Capacity Macro **AT THE TOP OF THE FILE** (Global Scope).
   - **Usage Rule:** You **MUST** use the macro name in `BUG_ASSERT`. Do NOT write the raw number.
   - **Prohibited:** `BUG_ASSERT(len < 4096);` (Bad log: "len < 4096")
   - **Required:** `BUG_ASSERT(len < ENTRY_CAP);` (Good log: "len < ENTRY_CAP")
   - **Pattern:**
     ```c
     /* --- Global Constants --- */
     #define ENTRY_CAP 4096 
     
     /* --- Target Function --- */
     void target(...) {
         /* Semantic Assertion: explicit macro usage */
         BUG_ASSERT(len < ENTRY_CAP); 
         REACH_ASSERT;
         ...
     }
     
     /* --- Main Harness --- */
     int main() {
         /* Allocation linked to the same macro */
         entry->name = malloc(ENTRY_CAP);
     }
     ```

4. **Allocator Fidelity (CRITICAL):**
  - Your allocator stubs (e.g., wrapper_malloc, custom_alloc) MUST respect the size argument passed to them.
  - **Prohibited:** Do NOT ignore the argument and substitute a symbolic global variable.
  - *Wrong:* `void* my_malloc(size_t n) { return malloc(global_sym_size); }`
  - *Right:* `void* my_malloc(size_t n) { return malloc(n); }`

SYMBOLIC BOUNDARY & STUBBING
============================
1.  **Entrypoint Selection (CRITICAL):**

3.  **The Horizon:** Stubs must return **fully symbolic data**.
4.  **Loops:** Use concrete bounds for setup, but unconstrained bounds for the target logic.
